# 网页版本控制 PRD

**状态：** 用户已确认；首期源码实现完成
**日期：** 2026-11-17
**适用项目：** Epiph-code Studio
**本阶段：** 版本控制首期和截图本地存储源码已实现，待编译与运行验证

## 1. 背景与问题

当前应用的生成代码保存在应用对应的固定输出目录中。再次生成或修改时，新代码可能覆盖已有内容；系统没有为每次成功迭代保留独立快照，也没有在对话中选择旧网页版本的能力。

已部署网页另存于部署目录。工作台预览、生成目录和部署目录可能指向不同内容，用户无法确认当前看到、正在修改和线上发布的分别是哪一版。现有对话日志能回看提示词和工具事件，但不能把某一轮对话与可预览、可部署的代码快照可靠关联。

用户需要在对话中查看和选择网页版本、基于指定版本继续修改，并明确选择某个版本部署；历史版本应可追溯，不能因新一轮生成而丢失。

## 2. 产品目标

1. 每次成功生成或修改都创建一个独立、不可变的网页版本。
2. 用户可从对话工作台浏览版本历史并预览任意版本。
3. 用户可选择历史版本作为后续修改的基线，产生新的版本分支，不覆盖其他版本。
4. 用户明确选择待部署版本；部署成功后，线上地址指向该版本。
5. 对话轮次、提示词、生成 Agent、代码类型、版本关系和部署记录可相互追溯。
6. 生成失败或部署失败时，现有工作版本、历史版本和线上版本保持可用。

## 3. 非目标

- 不实现 Git 仓库、命令行 Git 操作或多人协作分支。
- 不承诺恢复版本功能上线前已被覆盖、且文件系统与数据库都未保留的代码历史。
- 不在生成成功后自动发布线上版本。
- 不在首期实现逐行视觉设计差异、页面截图像素对比或跨应用版本迁移。

## 4. 核心概念

| 概念 | 含义 |
|---|---|
| 工作版本 | 当前应用继续迭代的主版本。首次生成后成为 V1，此后新版本默认以当前工作版本为父版本。 |
| 预览版本 | 当前工作台右侧 iframe 正在展示的版本。默认等于工作版本；用户可临时切换为任意历史版本预览。 |
| 修改基线 | 下一轮 AI 修改读取的父版本。默认等于工作版本；用户可明确选择历史版本并从该版本继续修改。 |
| 已部署版本 | 当前线上部署目录实际对应的不可变版本。只有用户执行部署且部署成功后才更新。 |
| 应用版本 | 一次成功代码生成、修改或基线恢复后形成的不可变文件快照，拥有应用内单调递增的版本号。 |

预览历史版本不会自动改变工作版本、修改基线或已部署版本。选择“基于此版本继续修改”后，后续生成会以该版本为父版本并创建新的版本号。

## 5. 用户与权限

- 应用创建者可查看版本历史、切换预览、选择修改基线、比较版本、部署版本。
- 管理员沿用项目现有管理权限，可查看和管理应用版本。
- 非创建者不能读取应用私有版本文件、部署未公开版本或改变应用版本指针。
- 公开部署地址只读取当前已部署版本，不暴露工作目录、快照文件系统路径或未部署的历史版本。

## 6. 主要用户流程

### 6.1 首次生成

1. 用户在应用工作台发起生成。
2. 系统按用户选定的基线恢复应用工作区并串行执行生成；正式版本快照不接受模型工具写入。
3. 生成流正常结束，并且 Vue 项目构建成功后，系统提交不可变快照并创建 V1。
4. 工作版本、默认预览版本和本轮对话关联到 V1。
5. 线上版本仍为空，用户可以稍后选择 V1 部署。

### 6.2 对话修改并创建新版本

1. 用户发送修改请求。系统将选定基线恢复到应用级互斥工作区，AI 在该工作区中修改；历史快照始终只读。
2. 生成或构建成功后，创建新的版本，例如 V2，并记录父版本为 V1、关联本轮 `turnId` 和用户提示词。
3. 工作版本和预览版本切换到 V2；V1 快照不变。
4. 若生成或 Vue 构建失败，系统恢复原工作区和工作版本；聊天中显示失败原因。

### 6.3 查看和比较历史版本

1. 用户在对话标题附近打开版本历史面板。
2. 时间线显示版本号、创建时间、关联对话摘要、Agent、代码类型、父版本，以及“工作版本”“已部署”等状态标记。
3. 用户选择一个版本后，右侧预览加载该版本，界面明确显示版本号。
4. 用户可选择两个版本比较：文本文件显示文件级变更和统一 diff；图片、二进制和超大文件显示新增、删除或变更状态，不尝试渲染文本 diff。
5. 用户可点击“基于此版本继续修改”设置修改基线。新一轮成功后创建该版本的子版本。

### 6.4 部署指定版本

1. 用户在版本历史中选择“部署此版本”，或从工作版本的部署操作中选择目标版本。
2. 系统在确认框显示目标版本号、创建时间和关联提示词摘要。
3. 用户确认后，系统将所选快照原子复制到部署目录。
4. 部署成功后更新应用的已部署版本指针，并记录部署人、时间和版本号；部署 URL 保持稳定。
5. 部署失败时，保留原部署文件和已部署版本指针，并显示可操作的错误信息。
6. 用户选择旧版本再次部署即可回滚；回滚本身生成一条新的部署记录，不删除新版本。

## 7. 功能需求

### 7.1 版本创建与不可变快照

- HTML、原生多文件和 Vue 工程三种现有代码类型均纳入版本管理。
- 每轮生成或修改只有在生成流正常结束、且 Vue 项目构建成功后才创建正式版本。
- 在正式版本提交前，原工作版本和线上版本保持可访问；不允许模型工具直接覆盖历史快照。生成使用应用级互斥工作区，预览和发布均从不可变快照读取。
- 暂存快照完整保存预览和部署所需的文件。Vue 工程需保存源代码及可复用的构建产物，保证历史版本可独立预览和部署。
- 版本记录至少包含：版本 ID、应用 ID、版本号、父版本 ID、关联 `turnId`、提示词、生成 Agent、代码类型、文件清单及校验摘要、创建人、创建时间、状态。
- 应用版本号在单个应用内严格递增；分支版本也使用新的全局应用版本号，并保留父版本关系。
- 暂存目录提交采用原子切换或等效方案。失败目录可清理，不得被版本列表显示为成功版本。

### 7.2 版本查看与对话关联

- 版本历史以对话工作台中的抽屉或侧栏呈现，不挤压现有双栏对话与网页预览主区域。
- 每轮成功生成的 AI 回复旁显示版本标记，例如“生成了 V4”。
- 版本列表支持按时间倒序查看；工作版本和已部署版本有清晰状态标识。
- 预览区显示当前预览的版本号和状态；刷新或重开工作台后，默认选中工作版本。
- 历史预览使用版本专属 URL 或不可复用的缓存标识，不能因应用的最新文件更新而串版。

### 7.3 修改基线与分支

- 用户查看历史版本时，可以单独设置“基于此版本继续修改”。
- 设置后，界面常驻显示当前修改基线；新一轮生成将该版本快照恢复到应用工作区再继续修改。
- 完成后产生新的子版本，工作版本切换到新版本；其他分支和版本保持不变。
- 用户只预览历史版本但没有选择“继续修改”时，发送消息仍以当前工作版本为基线，避免误改旧版本。
- 生成过程中记录所用父版本 ID；如父版本已被其他请求更新，拒绝静默覆盖并提示用户刷新或重新选择基线。

### 7.4 版本部署

- 部署操作必须携带明确的版本 ID；禁止用“当前目录最新内容”隐式替代目标版本。
- 新版本生成成功后不自动更新线上版本。
- 部署前对 Vue 版本使用该快照对应的构建产物；必要时从该快照重新构建，不能读取其他版本的 `dist`。
- 部署文件完整校验通过后再更新 `deployedVersionId`；切换失败时恢复旧部署目录。
- 部署后，工作台的已部署预览和线上地址读取指定版本；缓存键包含版本标识。
- 首页作品卡明确展示部署状态和部署版本；未部署应用默认展示工作版本预览。

### 7.5 版本比较

- 支持选择两个版本进行比较。
- 展示新增、删除、修改的相对文件路径。
- 文本文件在受支持的文件大小范围内展示统一 diff；超限或二进制文件只显示文件状态和大小。
- 版本比较只读，不改变工作版本、修改基线、预览选择或部署状态。

### 7.6 旧应用接入

- 功能上线后首次访问已有应用时，若尚无版本记录，系统将当前生成目录保存为“历史基线”版本，并保留其已有文件。
- 若现有部署目录与当前生成目录内容不同，额外保存为“历史部署基线”，并将已部署版本指向该快照。
- 旧对话可以作为提示词参考，但无法证明某一轮对话对应某份已被覆盖的文件；系统不得伪造历史版本或精确修改时间。
- 基线创建幂等，重复访问不得产生重复版本。

### 7.7 存储和清理

- 首期保留每个成功版本，不自动删除、不覆盖。
- 版本列表显示快照创建时间和可选的文件总大小。
- 暂存失败文件允许由系统安全清理；正式版本的手动删除不纳入首期。
- 后续可根据实际磁盘使用制定保留策略和去重方案，不影响本期不可变语义。

### 7.8 应用截图存储

- 当前本地开发默认将应用封面截图保存在统一产物目录 `tmp/screenshots/`，不要求配置腾讯云 COS，也不因 COS 未配置而导致部署流程报错。
- 后端提供受路径约束的静态资源地址，应用封面保存为该本地静态 URL；截图生成或文件写入失败时保留现有封面，并记录错误。
- 本地截图生成后保留在磁盘；生成或封面更新失败时保留应用当前封面，不因请求结束而删除截图文件。
- 本方案适用于单机开发和单体部署。若未来运行多实例或需向公网长期提供封面，再接共享磁盘或对象存储；存储实现不得耦合网页生成与部署成功状态。

## 8. 页面与交互建议

1. 对话页应用标题旁增加“工作版本 Vn”入口；点击后打开版本时间线。
2. 版本条目显示版本号、时间、提示词摘要、分支来源和状态标签。
3. 选择版本后，预览栏标题同步显示“预览 Vn”；顶部提供“基于此版本继续修改”“比较”“部署此版本”操作。
4. 当前正在编辑的基线与预览版本不一致时，在输入区域上方显示提示，例如“正在预览 V2；本轮修改仍基于 V5”。
5. 部署版本通过确认弹窗完成，成功后显示“线上版本已更新为 Vn”。
6. 首页作品卡在“已部署”状态下显示部署版本号；尚未部署时显示工作版本号。
7. 生成中不更新工作版本指针；新版本提交成功后再更新界面状态。

## 9. 数据和接口建议

### 9.1 数据对象建议

- `app_version`：版本元数据、父版本、对话轮次、文件 manifest、创建状态及时间。
- `app_deployment_history`：应用、版本、部署人、部署时间、部署结果和错误信息。
- `app` 增加或维护工作版本与已部署版本指针；预览选择可保存在前端会话状态，不作为应用全局指针。
- 文件系统按应用和版本隔离，例如 `code_versions/{appId}/{versionId}/`；正式快照禁止写入。

### 9.2 接口能力建议

- 查询应用版本列表及版本详情。
- 读取指定版本的预览资源。
- 选择修改基线并发起对话生成。
- 比较两个版本的文件 manifest 和文本 diff。
- 部署指定版本并查询部署记录。
- 查询当前工作版本和已部署版本状态。

接口路径、数据库字段和目录布局在需求确认后根据现有单体与微服务结构确定，本 PRD 不预先锁定实现细节。

## 10. 验收标准

1. 首次成功生成创建 V1；再次成功修改创建 V2，V1 文件哈希和预览内容不变。
2. 修改失败或构建失败时，不产生成功版本，工作版本和已部署版本指针均不改变。
3. 工作台可预览 V1、V2 等任意版本；刷新页面后仍加载所选版本内容，不显示其他版本文件。
4. 选择 V1 作为修改基线后生成成功，创建新版本并将 V1 记录为父版本；V2 仍可查看和部署。
5. 只切换预览版本不改变修改基线，避免下一轮消息无意间基于历史版本修改。
6. 部署指定版本后，线上 URL、工作台已部署预览和“已部署版本”标记均对应所选版本。
7. 部署失败时，原线上网页仍可访问，版本时间线保留失败记录或明确错误，不误标为新版本已部署。
8. 从历史版本回滚部署不会删除之后创建的版本，且部署历史可追溯。
9. 首页作品卡展示当前已部署版本；未部署应用展示工作版本，且缓存不会导致跨版本旧页面。
10. 旧应用首次接入版本管理时保留当前生成内容；若部署内容与生成内容不同，两份内容均可查看。历史轮次与文件无法可靠匹配时标为“历史基线”。
11. 所有版本读写、基线选择、比较和部署操作遵守应用所有者及管理员权限。
12. HTML、多文件和 Vue 三种代码类型均覆盖创建、预览、比较和部署流程。
13. 未配置 COS 时，部署后截图仍能本地生成、经静态路由读取并更新封面；截图失败不影响部署结果，也不覆盖已有封面。

## 11. 风险与待确认假设

- **磁盘占用：** 完整快照会随版本数增长。首期保留所有成功版本，需监控磁盘空间；后续可评估文件级去重。
- **生成过程隔离：** 当前代码工具写入应用固定工作区；服务按应用串行生成，并在失败时恢复基线。工作台与首页优先从不可变快照预览，部署也只读取选定快照。
- **Vue 构建成本：** 版本预览和部署必须使用匹配的构建产物，避免版本选择后又构建或复制到错误目录。
- **历史不可恢复：** 上线前已覆盖的代码若无备份，无法还原真实版本；迁移时只建立有文件证据的基线。
- **发布语义：** 本草案采用“生成不发布、用户选择后发布”的规则；每次部署都记录目标版本。
- **失败处理：** 版本快照写入、版本指针更新、部署目录切换应具备一致性和可恢复策略。

## 12. 首期完成定义

- 三种现有代码类型均以不可变快照生成版本。
- 对话工作台拥有版本时间线、版本预览、修改基线选择、版本比较和指定版本部署。
- 工作版本、预览版本和已部署版本状态清晰分离。
- 新生成不会覆盖旧版本或自动覆盖线上版本。
- 旧应用能够安全建立历史基线，权限和失败回滚满足验收标准。
- 相关迁移脚本、接口说明和用户可见错误状态齐备。

## 13. 实现映射

- 网页快照位于统一存储根目录 `tmp/code_versions/{appId}/{versionId}`；活动生成工作区位于 `tmp/code_output/`，部署内容位于 `tmp/code_deploy/`。
- 后端提供版本列表、版本比较、部署历史和按版本部署接口；历史快照预览使用版本专属静态资源路由。
- 对话工作台提供版本时间线、预览切换、修改基线选择、文本差异查看和指定版本部署；作品卡展示当前线上版本号或工作版本号。
- 新部署必须显式携带版本 ID。版本生成不会自动更新线上目录。
- 应用截图默认使用 `tmp/screenshots/` 本地文件，并通过静态资源路由供封面读取；COS 不再是本地运行的必需依赖。
- 已逻辑删除（`isDelete = 1`）的应用默认在数据库保留 30 天（可通过 `epiphcode.cleanup.retention-days` 配置）；`AppCleanupService` 在服务启动完成及每日凌晨 3 点自动扫描超过保留期的已删除应用，递归清理 `tmp/code_output/*_{appId}`、`tmp/code_versions/{appId}`、`tmp/code_deploy/{deployKey}` 与关联封面截图，并物理删除数据库主表及版本/部署/对话关联记录，以控制长期磁盘占用。
- 现有数据库升级需执行 `sql/migration_app_versions.sql`；源码阶段仅做静态核对，实际构建和运行验证需在数据库迁移后完成。
